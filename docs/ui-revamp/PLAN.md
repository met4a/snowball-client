## 2. How the current UI is built (recon)

- **View layer, written once for every version.** `ui/View` (a full-screen piece of UI), `ui/Canvas` (fills, text, textures, pose stack), and `ui/Host` (navigation, textures, keys).
  - The modern versions show a View inside `platform/ViewScreen` (a vanilla `Screen`), with `platform/GuiCanvas` over `GuiGraphics(Extractor)`.
  - 1.8.9 uses `LegacyScreen` and `LegacyCanvas`.
  - Every surface is drawn from fills and texture blits. **There are no custom shaders today.**
- **Look.** `gui/Glass` draws "Liquid glass", "Frosted glass" and "Classic" from plain fills: a gradient body, a rim lit from one direction, a sheen, an accent glow, and shadow layers. `gui/theme/Theme` holds the values (`gui.json`, schema 1). Menu & Accessibility (`InterfaceSettings`) offers:
  - palette (6 named pairs), look, blur behind, smooth text
  - menu colour, panel colour, scale (0.5–2.0), high contrast
  - background dim, panel opacity, animation speed (0 = off), pause game
  - Snowball main menu, Snowball loading screen
- **Blur.** "Blur behind menus" calls vanilla's menu blur through `Screen.extractBackground`. The `Glass GUI` module (`render/GlassGui`) makes vanilla screens see-through, through `ScreenBackgroundMixin`.
- **Motion.** `gui/anim/Smoothed` (exponential approach, frame-rate independent through `FrameClock`). Springs are not implemented.
- **3D Menus.** `module/client/Menu3D` has two styles:
  - *Lean*: `ui/Depth` shears the 2D pose, and panels draw a thickness slab.
  - *Windows*: in a world, Views open as panes standing in the world (`spatial/*`, `platform/SpatialGame`, drawn through `LevelRenderEvents.COLLECT_SUBMITS` / `WorldRenderEvents.BEFORE_ENTITIES`).
- **Modules.** `module/Module` has an id, name, **description** (all modules have one), category, settings and keybind. It also supports advanced-only, extra categories, and a status badge such as "NOT INSTALLED". There are 10 categories (`ModuleCategory`).
  - Setting types: Boolean, Choice, Color (with presets and alpha), Number (min, max, step, unit) and String. Settings can be hidden.
  - Profiles: Config Profiles, Mod Profiles, Presets. There are **no module favourites**.
- **HUD.** `hud/HudModule`: position is stored as a fraction (0–1) of the free screen space, plus scale, rotation, lock, background and background opacity. One `HudRenderer` is registered with `HudElementRegistry.addLast`. Vanilla's F1 already skips it. About 22 HUD modules (section 3).
- **HUD editor** (`gui/HudEditorView`) already has drag, corner-resize, rotate knob, 8 px grid (G), centre magnets and guides, arrow nudge, lock (L), undo/redo and reset (R).
- **Notifications.** `hud/NotificationCenter`: up to 4 cards at the top right, slide-in and fade, drawn by the HUD renderer.
- **Config.** `config/ConfigManager` writes `config/snowballclient/{client,modules,keybinds,gui,waypoints}.json` and `profiles/*.json`. `JsonConfigFile` has versioned step migrations.
- **Keybinds.** Right Shift opens the menu (`key.snowballclient.open_menu`) and B opens the emote wheel. Spotify keys are unbound by default. Module keybinds go through `KeybindTracker`.
- **FPS Boost.** `module/fps/FpsBoost` has presets max_fps, balanced and quality, plus external-mod modules that request Sodium and others through the launcher. The launcher's "FPS Boost" profile installs **Sodium, Lithium, FerriteCore, ImmediatelyFast and EntityCulling**. "Visual Quality" adds **Iris**. Neither is bundled in the client jar.
- **Mixins that touch rendering or screens:**
  - `ScreenBackgroundMixin` (blur and menu background)
  - `LoadingOverlayMixin`
  - `SetScreenMixin` (title replacement)
  - `GameRendererMixin` (hurt shake, FOV)
  - `LevelRendererMixin` (block outline)
  - `TextureAtlasMixin`, `OverlayTextureMixin`, `LightmapRenderStateExtractorMixin`
  - `CrystalGlowMixin`, `NameTagMixin`, `OwnNameTagMixin`, `PlayerTabOverlayMixin`
  - `ParticleEngineMixin`, `WeatherEffectRendererMixin`, `ScreenEffectRendererMixin`
  - `EntityRenderDispatcherMixin`, `BlockEntityCullingMixin`
  - `MouseHandlerMixin` (input for windows in the world)

**Material levels** (`glassLevel` 0–100; the Transparency slider):

| Stop | Level | Blur | Base tint α | Saturation | Rim |
|---|---|---|---|---|---|
| Ultra Clear | 0 | ½ level, light | 0.18 | 1.30 | 1.00 |
| Clear | 25 | ½ to ¼ | 0.32 | 1.25 | 0.90 |
| Regular (default) | 50 | ¼ | 0.48 | 1.20 | 0.75 |
| Thick | 75 | ¼ to ⅛ | 0.66 | 1.15 | 0.60 |
| Fully Tinted | 100 | ⅛ | 0.86 | 1.10 | 0.45 |

Starting values, to be tuned in the Glass Lab.

**Legibility rule (Golden Gate):** the effective tint α is `max(baseTint(level), αNeeded(L))`, where L is the linear luminance of the backdrop under the panel, read from the ⅛ level. αNeeded makes the composited backdrop dark enough for `#F2F6FA` text to reach 4.5:1 and for secondary text to reach 3:1, with the backdrop darker than the text. Worked example: over blurred snow (L ≈ 0.9), primary text needs a backdrop luminance ≤ 0.166. Blending happens on gamma-encoded values, as in the game's colour target, and the clear-glass secondary grey (`#A9B8CC`) needs ≤ 0.12. So α ≈ 0.63, even at Ultra Clear (the base tint there is 0.18). This is checked in `SnowglassTest`; an earlier draft of this plan said 0.82 because it blended in linear light. The slider sets the floor; legibility sets the ceiling. A unit test sweeps L over [0, 1] at every stop and asserts ≥ 4.5:1 for primary text and ≥ 3:1 for secondary text.

## 6. Render architecture

### 6.1 Frame flow (both modern versions; hook *verified*)

```
GameRenderer frame
 ├─ level (Sodium / Iris) → main colour target
 ├─ GUI extraction: Hud + Screen.extractRenderState(...)
 │     Snowglass components submit GlassElement render states into GuiRenderState
 │     and set SnowglassFrame.wantsGlass = true
 └─ GuiRenderer.render() → prepare() → draw()
        @Inject(HEAD) draw  ← the only new rendering injection
          if wantsGlass && quality != OFF && backend ok:
             Backdrop.build(mainTarget):      copy main colour → full-res copy
                                              dual-Kawase down: full→½→¼→⅛
                                              dual-Kawase up:   ⅛→¼'→½'  (Full only)
        draw strata before blur → [vanilla processBlurEffect()] → strata after blur
          GlassElement batches: pipeline snowball:glass, TextureSetup(½', ¼'/⅛, ⅛), linear/clamp
```

Evidence:
- **26.2.** `GuiRenderer.draw()` sets the projection, draws "before blur", clears depth, calls `GameRenderer.processBlurEffect()`, then draws "after blur".
- **1.21.11.** `GuiRenderer.draw(GpuBufferSlice)` has the same order, with `processBlurEffect()` at the matching point.
- **Extraction comes first.** Extraction happens before `GuiRenderer.render`, so `wantsGlass` is known at `draw()` HEAD. That gives "skip the whole pass on frames with no visible glass" at no cost.
- **Why HEAD of `draw()`.** That is where vanilla's own menu blur point lives (it is in the same method). The main target there holds the finished world, including Iris's composite and the hand, and no GUI yet.
- **No Fabric event fits.** The two Fabric API rendering-v1 builds checked in the Gradle cache (25.3.3 and 27.0.14, both 26.x builds; the 1.21.11 build is *to verify*) have HUD, level and picture-in-picture hooks, but nothing between the level render and the GUI draw. `LevelRenderEvents.END` fires before the hand and post effects.
- **Trade-off.** Glass refracts the world, not GUI drawn below it (chat, the hotbar). That matches how vanilla's blur treats them.

### 6.2 Submitting glass (verified API)

- `GuiElementRenderState` (26.2 `net.minecraft.client.renderer.state.gui`, 1.21.11 `net.minecraft.client.gui.render.state`) exposes `buildVertices(VertexConsumer)`, `pipeline()`, `textureSetup()`, `scissorArea()` and `bounds()`.
- `GuiRenderState.addGuiElement(...)` places an element above anything it overlaps, so **text drawn after a panel always lands on top of it**, whatever the pipeline order.
- `GuiRenderer` batches by scissor, pipeline sort key and `TextureSetup`. It binds `Sampler0`–`Sampler2` from `TextureSetup` and sets `Projection` and `DynamicTransforms`; 1.21.11 also sets `Fog`. It allows **any vertex format per pipeline**: `getVertexFormatBinding(0)` in 26.2, `getVertexFormat()` in 1.21.11.
- Consequence: **no custom uniforms reach a GUI draw.** All per-panel data goes through vertex attributes, and frame data goes through the three samplers. `textureSize()` in GLSL gives the backdrop size. This matches the brief.
- `GuiGraphics(Extractor).guiRenderState` is `private` / package-private on both versions. That needs one `@Accessor` mixin (no injection, no behaviour change), plus the existing scissor stack for clipping.
- One frame-wide `TextureSetup` instance, so every glass element in a node batches into one draw.

### 6.3 Vertex data (per-version seam)

| Field | 26.2 (`VertexFormat.builder().addAttribute(name, GpuFormat)`, *verified*) | 1.21.11 (`VertexFormat.builder().add(name, VertexFormatElement)`, *verified*) |
|---|---|---|
| position | `Position` RGB32 float | `POSITION` |
| tint RGBA | `Color` RGBA8 unorm | `COLOR` |
| local px (from centre) | `Local` RG32 float | `UV0` (float2) |
| half size, radius | `Shape` RGB32 float | `UV1` + `UV2` (short2 ×2, fixed point ×8) |
| level, rim, flags, focus | `Params` RGBA8 unorm | `NORMAL` (byte3) + colour alpha |

On 1.21.11 Snowglass reuses vanilla's existing elements instead of calling `VertexFormatElement.register`. That registry is global and capped (`MAX_COUNT`), and Iris registers its own ids, so a new id risks a collision. Local coordinates go through the pose, so sheared "Lean" panels and rotated HUD elements keep a correct SDF.

### 6.4 Shaders

- `assets/snowballclient/shaders/core/snowglass.vsh/.fsh` follow vanilla conventions (*verified* from the 26.2 jar):
  - `#version 330`
  - std140 `DynamicTransforms` and `Projection` blocks, copied inline the way `gui.vsh` does
  - `uniform sampler2D Sampler0..2`
- Bind groups:
  - **26.2:** declared through `BindGroupLayout.builder().withSampler(..)` together with vanilla's matrices/projection layout. A duplicate name across layouts is a compile error.
  - **1.21.11:** declared with `withSampler` / `withUniform`.
- 26.2 compiles the same GLSL to SPIR-V for Vulkan (`GlslCompiler`).
- Fragment steps:
  1. Rounded-rect SDF, anti-aliased with `fwidth`.
  2. Backdrop UV from `gl_FragCoord / textureSize(Sampler0, 0)`.
  3. Lensing: offset along the SDF normal inside a 12 px bezel, 8 px at the rim (Full only).
  4. Dispersion: ≤ 1 px per channel at the rim (Full only).
  5. Mix the sharp level (`Sampler0`) and the frosty level (`Sampler1`) by panel size and level.
  6. Saturation boost.
  7. Adaptive tint from `Sampler2` (⅛ level, centre and 4 taps).
  8. Rim: one light from the top-left, optional drift with the mouse.
  9. Bottom inner shade.
  10. Grain of about 1.5%.
- Pyramid passes: `snowglass_down.fsh` / `snowglass_up.fsh` with vanilla's `core/screenquad` vertex shader (*verified*: `gl_VertexID`, 3 vertices, no vertex buffer). Texel offsets come from `textureSize()`, so these passes need no uniforms either.
- Outer shadow: drawn as part of the same quad (expanded bounds, SDF falloff), not as a separate element.

### 6.5 Text

- Keep `SmoothText`; replace the Nunito faces with Inter Regular, Medium and SemiBold (OFL; the licence goes in the jar next to the existing `fonts/OFL.txt`).
- Why not the vanilla TTF provider? It exists on 26.2: `TrueTypeGlyphProviderDefinition(location, size, oversample, shift, skip)`. But SmoothText already rasterises at the exact device-pixel size at every GUI scale, which an oversampled provider can't match. It also works unchanged on 1.8.9, and it is not affected by 26.2's `Font` changes (the draw methods are gone; text is now prepared and submitted).
- **Tabular figures:** `java.awt` can't switch on OpenType `tnum`, so SmoothText gives digits a fixed advance (the widest digit) for HUD values.
- HUD text is cached and refreshed at 4–10 Hz per element.

### 6.6 Version seam

These are thin interfaces. Version-agnostic code (tokens, layout, components, springs, config) stays in shared packages.

- **`GlassBackend`:** `isAvailable()`, `beginFrame()` and `panel(…)`.
  - `FillGlassBackend` (shared): the Off material through `Canvas` fills. It is what **1.8.9**, **windows in the world** and **Off** use.
  - `ShaderGlassBackend` (modern, `platform/`): one class with Stonecutter `//? if` blocks for the format and bind-group differences.
- **`UiTextRenderer`:** SmoothText or the vanilla font. It already exists as `UiText`; it gets formalised.
- **`UiInput`:** keys, focus, clipboard. It already exists as `Host`; it gets formalised.
- **`Canvas`** gains one default method, `glass(GlassSpec)`. Its fill-based default keeps `LegacyCanvas` and `WorldCanvas` compiling unchanged. `GuiCanvas` overrides it to submit the shader element.

### 6.7 Fallbacks and lifetime

- **Quality:** Off = `FillGlassBackend`; Lite = ¼ and ⅛ levels only, no lensing, no dispersion, no up passes; Full = everything.
- **Automatic downgrade:**
  - pipeline compile failure or texture creation failure → **Off** for the session, logged once, with one notification
  - an Iris shader pack in use → **Lite** (checked by reflection on `net.irisshaders.iris.api.v0.IrisApi`, no compile dependency; *to verify* in M7)
  - the 1.8.9 build → **Off** by construction
- **GPU resources:**
  - Recreated when the main target size changes; closed on `CLIENT_STOPPING` and on resource reload.
  - Textures and views are created through `GpuDevice.createTexture` / `createTextureView` (*verified* on both versions), and samplers through `RenderSystem.getSamplerCache()` (*verified* in 26.2 bytecode; for 1.21.11 it is documented in the primer, *to verify* in the jar).
  - Zero raw GL/LWJGL-GL calls. An M2 check greps the new code for `org.lwjgl.opengl` and `GL1`/`GL3` imports.
- **Vanilla blur.** Snowball screens stop asking vanilla to blur when quality is Lite or Full, since the panel blurs itself. The world outside the window gets the existing dim, and optionally vanilla's blur through the kept "Blur behind menus" setting. `blurBeforeThisStratum` is allowed only once per frame, so Snowglass never calls it itself.
- **Allocations.** Glass render states come from a per-frame pool, reset when the frame starts. Vertex writes go straight into vanilla's consumer. No per-frame allocation on the glass path; existing HUD string building is fixed in M5.

## 9. Config changes and migration

`gui.json` (Theme) schema 1 → 2, through the existing `JsonConfigFile.migration(1, …)`:

| New key | Values (default) | Migrated from |
|---|---|---|
| `glassQuality` | `off` / `lite` / `full` (`full`) | `style`: liquid → full, frosted → lite, classic → off |
| `glassLevel` (the Transparency slider) | 0–100 (`50`) | `panelOpacity`: 0.82 (old default) → 50; below that linear 0.2–0.82 → 0–50; above it linear 0.82–1 → 50–100 |
| `hudGlass` | `auto` / `off` / `lite` / `full` (`auto`) | new |
| `reduceMotion` | bool (`false`) | `animationSpeed == 0` → true (animationSpeed is kept) |
| `font` | `inter` / `minecraft` (`inter`) | `smooth_font`: see Q3 |
| `scale` (Menu Scale) | 0.75–1.25 (`1.0`) | clamped from 0.5–2.0 (Q7) |

Unchanged: `accentColor` (Menu colour; keep `0xFF7FCBFF` in source), `surfaceColor` (Panel colour = glass base tint), `backgroundOpacity` (dim), `highContrast` (forces Off and solid at Fully Tinted, yellow focus), `blurBehind`. The old `style` and `panelOpacity` are still read for migration, then dropped from the written file.

**HUD** (`modules.json`, per HUD module; modern only):
- New settings `anchor` (9-way id) and `offset_x` / `offset_y` (GUI px).
- `x` / `y` are kept and hidden, and remain the fallback until the first render migrates them.
- 1.8.9 keeps fractional positions (it has its own `HudModule`).

**Glass GUI module:** its "Snowball panels" setting overlaps with Transparency. It gets hidden, and its value is ignored once Snowglass is on. Its own vanilla-backdrop options stay.

Each migration gets a test in `ConfigTest`, using a 1.10.0 `gui.json` and `modules.json` fixture.

## 12. Risks

1. **Scope.** About 55 shared UI files on three targets, plus replacing the menu's core interaction if Q1 is yes. Mitigation: every milestone keeps the game tests green and leaves the client shippable.
2. **The 1.8.9 build compiles the shared UI.** New components must avoid modern-only APIs. Mitigation: build `-p legacy` at every milestone; the shader path lives only in `platform/`.
3. **Vulkan is experimental in 26.2.** GLSL → SPIR-V differences (derivatives, integer attributes, precision) could break only there. Mitigation: plain float attributes and vanilla-style blocks; a Vulkan game test from M2 on.
4. **ImmediatelyFast** (in the launcher's FPS Boost profile) patches GUI and HUD batching, and may reorder or batch custom `GuiElementRenderState`s differently. Mitigation: compatibility run in M2, not only M7.
5. **Iris** shader packs may change the main target's content (HDR or colour space differences in the composite), so the adaptive tint could misread luminance. Mitigation: Lite when a pack is active; screenshot check.
6. **Ordering.** Pipelines sort by build order inside a GUI node. Overlap pushes elements to higher nodes, so text over glass is safe, but non-overlapping order can change. Mitigation: a game-test pixel check that text over glass stays visible.
7. **Legibility vs. the slider.** At Ultra Clear over snow the panel still darkens (by design), and users may read that as "the slider does nothing". Mitigation: a live slider preview, and a one-line hint under the slider.
8. **Top-centre notifications** collide with boss bars and titles. Mitigation: offset below boss bars, step down for titles.
9. **4K and low-end iGPUs.** The ½-res level at 4K is 1920×1080. Mitigation: Lite starts at ¼, and Auto quality drops to Lite when the measured pyramid cost exceeds budget (decided after M2 numbers).
10. **Launcher design test** pins the accent line in `Theme.java`. Mitigation: never change that literal or its format.
11. **Small type at GUI scale 1** (caption 8 px). Mitigation: floor at 9 px at scale 1 if M1 screenshots show it's needed.
12. **Multi-session continuity.** Mitigation: PROGRESS.md is updated after every milestone, listing what's verified and what isn't.
